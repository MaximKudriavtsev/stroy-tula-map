# F02. Фотографии, документы и файловое хранилище

**Цель:** Сайт и бот используют один сервис реальных проверенных файлов; приватные материалы доступны только уполномоченным.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P0
**Исполнитель:** Backend / медиа

## Готовый промпт для агента

Ты реализуешь фичу F02 «Фотографии, документы и файловое хранилище» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00. Разработка против AccessPolicy contract; интеграция с F01.

**Условие интеграции:** Обязательная готовность для F06, регистрации фото в F11/F12 и реальных GLB в F07.

**Потребляет:** MediaRef, SourceRef, AccessPolicy; S3 endpoint, bucket и credentials из окружения.

**Предоставляет:** POST assets, complete, access; внутренний MediaService.ingestBotPhoto и permission-aware asset lookup; в handoff задать точные сигнатуры и schemas в рамках v1.

## MVP — реализовать сейчас

1. Создать записи assets со статусами PENDING/READY/REJECTED, storage key, owner/resource link, mime, size, checksum и access. Публичные и закрытые ресурсы имеют раздельные политики выдачи.
2. Для MVP загружать через backend stream: фото JPEG/PNG/WebP до 10 MiB, PDF до 20 MiB, self-contained GLB до 15 MiB. Для F23 предусмотреть opt-in приём VIDEO MP4 до 100 MiB с проверкой контейнера; по умолчанию видео отключено. Это стартовые конфигурационные ограничения; возвращать 413/415 с понятной причиной.
3. Проверять фактический MIME/signature и декодируемость; не доверять filename и Content-Type. Фотографии перекодировать, делать thumbnail, убирать EXIF из выдаваемых копий. Не принимать SVG/HTML как фото.
4. READY выставлять после сохранения и проверки. Bot draft с PENDING/REJECTED фото не проходит регистрацию. Вложения обращения всегда PRIVATE; фотографию из обращения нельзя сделать публичной одним переиспользованием URL.
5. Выдавать короткоживущий подписанный URL только после resource access check. Подписанная ссылка не заменяет проверку прав при её выдаче. Метаданные private assets не входят в public DTO.
6. GLB проверить на корректный контейнер и встроенные ресурсы; запретить внешние URI и произвольные server-side загрузки. Геометрию и размер GPU-ресурсов дополнительно проверяет F07.
7. При прерывании upload оставить понятный статус и повторную загрузку; сборку orphan assets выполнять с grace period, не удалять связанные материалы.

## Проверяемые сценарии MVP

1. Файл HTML с расширением .jpg → REJECTED; корректное фото → READY и thumbnail.
2. Исполнитель чужой задачи не получает private signed URL.
3. Повтор complete идемпотентен; потерянный upload не создаёт READY.
4. Фото с EXIF выдаётся без EXIF, отдельно записанное место обращения сохраняется.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Перейти на прямую multipart загрузку через signed upload URLs с обязательной серверной финализацией.
2. Добавить quarantine/antivirus, версии объектов, lifecycle и восстановление удалённых файлов по политике хранения.
3. Вынести оптимизацию GLB/KTX2 и крупных изображений в worker с ресурсными лимитами и статусом обработки.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.
