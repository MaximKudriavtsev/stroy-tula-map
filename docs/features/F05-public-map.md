# F05. Публичная карта, список и карточки

**Цель:** Житель может найти объект, понять статус и открыть карточку на компьютере и телефоне; все расширения подключаются к одной карте.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P0
**Исполнитель:** Frontend карты

## Готовый промпт для агента

Ты реализуешь фичу F05 «Публичная карта, список и карточки» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

F00 contracts/fixtures. Разработка параллельно F03; live приёмка после F03.

## MVP — реализовать сейчас

1. Собрать layout: карта в основной области, поиск и фильтры, список результатов, карточка сбоку/в нижней мобильной панели. Состояния loading/error/empty обязательны.
2. Синхронизировать q, type, status, municipality, selectedId, camera и режим с URL. Debounce поиска; отменять устаревшие запросы, чтобы поздний ответ не заменял новую выборку.
3. MapLibre показывает кластеры и статусные маркеры. Цвет/иконка с легендой, UNKNOWN визуально различим; выбранный объект остаётся узнаваемым.
4. Реализовать MapRuntime по 01-contracts.md. Учитывать padding карточки в fit/flyTo; сохранять предыдущий обзор и восстанавливать его. Ручной жест отменяет программный перелёт.
5. В карточке вывести все имеющиеся реквизиты, source/asOf, progress только при known, media и пустые состояния. Для объекта без координат не запускать перелёт.
6. Облегчённый режим скрывает тяжёлые модели; отсутствие WebGL переключает на список и карточку. Ошибка подложки оставляет поиск и данные доступными.
7. Переход в MAX доступен при настроенном botName. Передать context по согласованному формату F12, показать выбранный объект. Без доступа к MAX кнопка объясняет недоступность, не сообщает фиктивную отправку.
8. Добавить keyboard focus, доступные имена кнопок, контраст и reduced motion. Не размещать приватные сведения об обращениях на публичной карте.

## Проверяемые сценарии MVP

1. Фильтр меняет list/map; обновление страницы восстанавливает фильтр и selectedId.
2. Выбор маркера открывает правильную карточку; back возвращает обзор.
3. Объект без геометрии находится поиском.
4. Эмуляция WebGL failure → рабочий список, без бесконечной загрузки.
5. Viewport 390x844: карточка прокручивается, кнопки не перекрыты; reduced motion отключает перелёты.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить сохранённые подборки, доступные share links, рендер публичной карточки для поисковиков при подтверждённой необходимости.
2. При росте набора измерить время GeoJSON и перейти на viewport loading/vector tiles без изменения API семантики.
3. Добавить техническую телеметрию ошибок карты и performance budgets на согласованном наборе устройств.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.
