# F06. Редактор объектов, геометрия и публикация

**Цель:** Сотрудник выполняет весь цикл управления объектом и не раскрывает черновые данные публично.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P0
**Исполнитель:** Frontend админки

Ты реализуешь фичу F06 «Редактор объектов, геометрия и публикация» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.

Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## MVP — реализовать сейчас

1. Реестр показывает проект, объект, отрасль, муниципалитет, строительный статус и отдельное состояние публикации. Добавить поиск, фильтры и переход к draft.
2. Форма редактирует обязательные поля, реквизиты, nullable сроки, source, dataOrigin и геометрию. Ошибка поля из API показывается у соответствующего ввода.
3. Редактор геометрии поддерживает точку, контур и трассу: создание, перемещение, удаление вершины, проверка геометрии. При удалении последней точки объект становится без координат, а не получает [0,0].
4. Загрузка фото/PDF через F02 с прогрессом и состояниями проверки. Не использовать object URL браузера как сохранённый URL.
5. Сохранение работает с If-Match. При 409 показать, что есть чужая редакция, дать загрузить актуальную и восстановить локальные значения осознанно; не затирать автоматически.
6. Предпросмотр использует draft DTO в защищённом режиме. Publish показывает ошибки готовности; успешный publish сообщает номер редакции. Проверить публичную карточку после инвалидации cache.
7. Архивирование явно обозначает снятие с карты, сохраняет запись для истории. Добавить предупреждение о несохранённых изменениях при уходе.
8. Панели событий/моделей/пользы подключать экспортами соседних фич. Не создавать дублирующие формы со своей схемой.

## Проверяемые сценарии MVP

1. Создать, сохранить, предпросмотреть, опубликовать: публичная карточка получает правильную редакцию.
2. Неопубликованное фото или новое поле draft отсутствует публично.
3. Два редактора → 409 с сохранением локального ввода.
4. Невалидный polygon показывает ошибку до публикации; объект без геометрии сохраняется.
5. Пользователь без objects.publish не публикует даже прямым HTTP запросом.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить сравнение редакций, комментарии согласования и массовые изменения с preview.
2. Поддержать проекты с несколькими сооружениями, сложные Multi-геометрии и адресные aliases.
3. Улучшить геопривязку модели: числовые transform inputs и визуальные handles с undo/redo.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F06
pnpm test:integration -- --feature=F06
pnpm test:e2e -- --feature=F06
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F06.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Сотрудник выполняет весь цикл управления объектом и не раскрывает черновые данные публично.
