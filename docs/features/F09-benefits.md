# F09. Мощности и польза для территории

**Цель:** Пользователь понимает, что именно добавлено и как получено итоговое число; отсутствие исходных данных видно.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P1
**Исполнитель:** Аналитика / backend + frontend

## Вход и зависимости

F00; F03 и publication; F08 для исторических итогов. Текущий MVP может работать без шкалы.

**Условие интеграции:** UI встраивается в F05 карточку и F06 редактор; муниципальные итоги F20 используют тот же calculator.

**Потребляет:** MetricInput/MetricResult, SourceRef, published objects/events.

**Предоставляет:** calculateBenefit; observations с источниками; benefits API и карточка «Было / Введено / Выбыло / Стало».

## MVP — реализовать сейчас

1. Создать справочник metricCode/unit и observations с территорией, периодом, source, FACT/PLAN и dataOrigin. Не смешивать места, койки, посещения/смену, квартиры, МВт, м³/сутки.
2. Реализовать calculateBenefit по 01-contracts.md. Показывать gross added даже когда netAdded неизвестен; after=null при неизвестном baseline или retired. Явно подтверждённое retired=0 допустимо.
3. Привязать baseline к дате, учитывать ввод/выбытие только после неё и до выбранного среза. Один event/contribution ID учитывается один раз, даже если связан с проектом и несколькими карточками.
4. Обеспеченность вычислять только для согласованных территории, периода, возрастной группы и denominator>0. Не переводить квартиры в жителей без отдельного источника.
5. Редактор позволяет задать значение, единицу, дату, источник и факт/план. Preview показывает, что можно посчитать, а чего не хватает.
6. В карточке выводить проверенные числа и причину пропуска расчёта. Пример DEMO: baseline=500, added=300, retired=100 → after=700, netAdded=200. При retired=null показать added=300, итог неизвестен.
7. На карте подсвечивать ServiceArea только при её наличии и источнике; площадь муниципалитета не выдавать за подтверждённую зону обслуживания.

## Проверяемые сценарии MVP

1. 500+300−100 → 700; netAdded=200.
2. baseline=null или retired=null → after=null; значение 0 не равно null.
3. Места/койки и разные периоды не суммируются.
4. Один введённый объект в двух выборках не удваивает вклад в общий итог.
5. PLAN и DEMO исключены из фактического REAL итога по умолчанию.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить граф связей замены/выбытия и распределение вклада по нескольким территориям с утверждённой методикой.
2. Подключить версии статистики населения и возрастные группы; показывать метод и дату расчёта.
3. Добавить uncertainty и диапазоны там, где источник даёт интервал, без превращения оценки в точный факт.
4. Кешировать территориальные агрегаты по revision/date/methodVersion, инвалидировать после публикации.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Опорные тесты для реализации

Файл tests/unit/F09-benefits.spec.ts. Реализация экспортируется из packages/domain/src/metrics/index.ts. Тесты фиксируют семантику неизвестного выбытия.

```ts
import { expect, it } from 'vitest';
import { calculateBenefit } from '../../packages/domain/src/metrics/index';

const input = {
  metricCode: 'SCHOOL_SEATS',
  unit: 'SEAT',
  territoryId: '00000000-0000-4000-8000-000000000001',
  baseline: 500, added: 300, retired: 100,
  denominator: null, per: null,
};

it('F09: учитывает замещение старых мощностей', () => {
  const result = calculateBenefit(input);
  expect(result.after).toBe(700);
  expect(result.netAdded).toBe(200);
  expect(result.provision).toBeNull();
});

it('F09: неизвестное выбытие не заменяется нулём', () => {
  const result = calculateBenefit({ ...input, retired: null });
  expect(result.after).toBeNull();
  expect(result.netAdded).toBeNull();
});

it('F09: подтверждённое нулевое выбытие позволяет расчёт', () => {
  expect(calculateBenefit({ ...input, retired: 0 }).after).toBe(800);
});
```
