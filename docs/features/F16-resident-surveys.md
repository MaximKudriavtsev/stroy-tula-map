# F16. Мнение жителей и окраска территорий

**Цель:** Карта мнений показывает источник и достаточность данных и не смешивает разные виды оценки.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2, зависит от источника опросов
**Исполнитель:** Аналитика / frontend

Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F05, границы территорий и survey schema; F01 для загрузки данных.

**Условие интеграции:** Отдельный map mode; не использовать число обращений как удовлетворённость.

**Потребляет:** SurveyAggregate, geometry territories, источник/методика/период/сектор/sample count.

**Предоставляет:** Survey import/read API, легенда и choropleth; не влияет на официальные показатели обеспеченности.

## MVP — реализовать сейчас

1. Создать агрегированную модель: territoryId, sector, questionCode, scaleMin/Max, value, responsesCount, period, source, methodology, minimumSample. Индивидуальные ответы для MVP не собирать.
2. Загружать подготовленные агрегаты с preview. При отсутствии реального источника показать «Данных об оценках пока нет»; DEMO слой включается отдельно с заметной маркировкой.
3. Проверять value внутри шкалы, nonnegative sample, известный период и совместимость вопроса при сравнении. Опросы с разными шкалами не нормализовать молча.
4. Окрасить районы по оценке выбранной отрасли/периода; недостаточные данные — нейтральный слой с пояснением, а не красная оценка.
5. Tooltip/карточка территории показывает value, число ответов, вопрос, источник, методику и дату. Не называть sample репрезентативным только из-за достаточного количества.
6. Отдельно отображать удовлетворённость инфраструктурой, обеспеченность и оценку ответа на обращение. Данные F25 не попадают в инфраструктурную удовлетворённость.

## Проверяемые сценарии MVP

1. Нет агрегата и sample ниже minimumSample → нейтральный цвет с разными пояснениями.
2. Неверная шкала/отрицательный sample отклонены.
3. Два опроса разных вопросов не складываются в одну оценку.
4. Фильтр отрасли/периода обновляет легенду и значения согласованно.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Подключить официальный survey provider через scheduled import с версиями и дедупликацией.
2. Добавить confidence interval только при предоставленной методике и данных; не вычислять его из одного среднего произвольно.
3. Версионировать территории и методики; разрешать сравнение динамики только совместимых рядов.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

Подготовь docs/handoffs/F16.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Карта мнений показывает источник и достаточность данных и не смешивает разные виды оценки.
