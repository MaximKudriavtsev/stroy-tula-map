# F17. Миниатюры объектов за краями карты

**Цель:** Житель видит ограниченное число полезных объектов вне экрана и может перелететь к ним и вернуться.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2
**Исполнитель:** Frontend карты

## Готовый промпт для агента

Ты реализуешь фичу F17 «Миниатюры объектов за краями карты» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## MVP — реализовать сейчас

1. После moveend определить кандидатов вне видимой области по отфильтрованному набору. Не учитывать объекты без координат и исключённые фильтром.
2. Спроецировать координаты в экран, получить направление относительно доступного прямоугольника карты с padding карточки. Не опираться только на geographic bearing при повёрнутой карте.
3. Сгруппировать близкие направления в 8 секторов, оставить не более 4 миниатюр на desktop и 2 на mobile. В секторе показывать ближайший кандидат по выбранной метрике и +N.
4. Миниатюра содержит preview либо иконку типа, короткое название и доступное имя. Не перекрывать легенду, controls и карточку; раскладка пересчитывается при resize.
5. Нажатие вызывает flyToObject(id,{rememberView:true}), кнопка назад — restoreView. Повторные клики и ручной жест отменяют прежний перелёт.
6. Пересчёт выполнять по moveend/resize, а не на каждом render; исключить дрожание выбора гистерезисом/стабильной сортировкой по ID.

## Проверяемые сценарии MVP

1. Объект внутри viewport не получает краевую миниатюру.
2. Поворот/наклон карты сохраняют правильное экранное направление.
3. Миниатюры не выходят за viewport и не превышают лимит.
4. Фильтр убирает кандидата; возврат восстанавливает предыдущий обзор.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить раскрытие группы направлений в список и пользовательские приоритеты подборки.
2. Предзагружать только маленькие thumbnails ближайших кандидатов; измерить стоимость на большом наборе.
3. Добавить клавиатурную навигацию между секторами и поведение для RTL при необходимости.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F17
pnpm test:integration -- --feature=F17
pnpm test:e2e -- --feature=F17
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F17.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Житель видит ограниченное число полезных объектов вне экрана и может перелететь к ним и вернуться.
