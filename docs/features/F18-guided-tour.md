# F18. Экскурсия «Итоги за минуту»

**Цель:** Экскурсия последовательно показывает реальные данные выбранного набора и всегда допускает ручное управление.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2
**Исполнитель:** Frontend сценариев

## Готовый промпт для агента

Ты реализуешь фичу F18 «Экскурсия «Итоги за минуту»» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F05 runtime; F08/F09 только если шаг использует историю/пользу.

**Условие интеграции:** MVP — подготовленный JSON маршрут из опубликованных объектов.

**Потребляет:** MapRuntime, public object IDs и карточки; curated tour schema в contracts/extras.

**Предоставляет:** Play/pause/next/back/exit экскурсия с источниками используемых показателей.

## MVP — реализовать сейчас

1. Определить tour schema: id/title/dataOrigin, шаги objectId/caption/durationSec/optionalAt. Подготовить 3–5 шагов DEMO по fixture объектам.
2. На старте сохранить view и filters; шаг вызывает существующий flyToObject и показывает пояснение из опубликованных данных. Не хардкодить в тексте неподтверждённые реальные числа.
3. Добавить pause/next/back/exit и прогресс. Таймер начинается после завершения перехода; суммарное время планировать около минуты, без жёсткого зависания при ошибке.
4. Ручное движение камеры ставит экскурсию на паузу. Выход восстанавливает прежний обзор и фильтры.
5. При отсутствующем/архивированном объекте показать причину пропуска и следующий доступный шаг; при отсутствии всех шагов — пустое состояние.
6. Reduced motion переключает шаги без анимированного полёта. Экскурсия не блокирует самостоятельную навигацию.

## Проверяемые сценарии MVP

1. Play→pause→resume не создаёт два таймера.
2. Exit возвращает camera/filter state.
3. Архивированный объект пропускается, тур не зависает.
4. DEMO тур маркирован, цифры соответствуют опубликованному fixture.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить CMS редактор туров и preview публикации с versioned schema через интегратора.
2. Поддержать тематические и муниципальные подборки, динамические шаги только из опубликованных объектов.
3. Добавить локализованные подписи и сохранение позиции прохождения без персональной аналитики по умолчанию.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F18
pnpm test:integration -- --feature=F18
pnpm test:e2e -- --feature=F18
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F18.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Экскурсия последовательно показывает реальные данные выбранного набора и всегда допускает ручное управление.
