# F19. Фотосравнение «До / Сейчас / После»

**Цель:** Сравнение помогает увидеть изменения и не выдаёт несопоставимые или проектные изображения за факт.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2
**Исполнитель:** Frontend медиа

## Готовый промпт для агента

Ты реализуешь фичу F19 «Фотосравнение «До / Сейчас / После»» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F02, F05 карточка; реальные сопоставимые фото при наличии.

**Условие интеграции:** Независимый компонент карточки; не меняет сохранённые оригиналы.

**Потребляет:** READY PUBLIC MediaRef с capturedAt/source и настройкой пары по object revision.

**Предоставляет:** Галерея по датам; сравнение двух подтверждённых фотографий; явная маркировка проекта будущего вида.

## MVP — реализовать сейчас

1. Показать фотографии по известным датам. Если дата неизвестна, вынести отдельно, не сортировать по дате upload как по дате съёмки.
2. Разрешить выбрать две фотографии с датами и подписями. Простое side-by-side сравнение — базовый режим, не требующий геометрической совместимости ракурсов.
3. Slider сравнения включать только для пары, которую редактор пометил сопоставимой по ракурсу/кадрированию. Несопоставимые фотографии остаются рядом.
4. «После» использовать для фактического состояния только при соответствующей дате и источнике. Проектная визуализация будущего помечается «Проектный вид» и не называется фотографией результата.
5. Добавить клавиатурное управление slider, touch, alt text, lazy loading и обработку отсутствующего изображения.
6. При отсутствии фото не создавать изображения реального объекта; показать состояние «Фотографии пока не добавлены».

## Проверяемые сценарии MVP

1. Неизвестная дата не превращается в дату загрузки.
2. Для разных ракурсов slider выключен, side-by-side работает.
3. Проектный render помечен отдельно от фактического фото.
4. Private asset никогда не используется публичным compare component.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить ручное non-destructive выравнивание и crop metadata с сохранением оригинала и версии пары.
2. Добавить несколько временных точек, таймлапс из одобренных фото и экспорт сравнения с датами/источниками.
3. Автоматическую регистрацию кадров принимать только как предложение редактору с preview.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F19
pnpm test:integration -- --feature=F19
pnpm test:e2e -- --feature=F19
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F19.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Сравнение помогает увидеть изменения и не выдаёт несопоставимые или проектные изображения за факт.
