# F20. Итоги муниципалитета и тематические подборки

**Цель:** Итоги территории прослеживаются до конкретных объектов и показывают полноту исходных сведений.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2
**Исполнитель:** Frontend + аналитика

## Готовый промпт для агента

Ты реализуешь фичу F20 «Итоги муниципалитета и тематические подборки» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F03, F05; мощности требуют F09, исторический срез F08.

**Условие интеграции:** Повторно использует единые calculators; не создаёт собственную формулу итогов.

**Потребляет:** Published projects/objects, MetricResult, at/from/to и dataOrigin filters.

**Предоставляет:** GET municipality summary и фильтрованные тематические ссылки на карту.

## MVP — реализовать сейчас

1. Сформировать summary по муниципалитету: число уникальных проектов и объектов раздельно, статусы, known/unknown counts, введено за период, доступные мощности по единицам.
2. Источник объектов — тот же published query, что карта. Сначала включить текущую сводку; при отсутствии F08 historical controls выключены явно.
3. Показать покрытие данных: сколько объектов без координат, подтверждённого статуса/мощности. Отсутствующие данные не исключать из знаменателя полноты молча.
4. Тематические подборки MVP — сохранённые параметры type/status/municipality с названием. Нажатие открывает карту с соответствующим URL state.
5. Показать таблицу/небольшие диаграммы и ссылки на вошедшие объекты. DEMO и PLAN итоги отделены от REAL FACT.
6. При фильтре периода точные и неполные даты обрабатывать по F08; не приписывать недатированный текущий ввод конкретному году.

## Проверяемые сценарии MVP

1. Один проект с тремя сооружениями → 1 project, 3 objects.
2. Summary total согласован со списком; отсутствие координат не вычёркивает объект.
3. Места и койки показаны разными рядами.
4. DEMO не меняет реальный summary по умолчанию.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Добавить редактируемые подборки с публикацией, versioned territorial boundaries и сравнение периодов.
2. Добавить выгрузку отчёта с источниками, охватом и методом расчёта.
3. Кэшировать по municipality/date/filters/revision и проверять invalidation после publish.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F20
pnpm test:integration -- --feature=F20
pnpm test:e2e -- --feature=F20
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F20.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Итоги территории прослеживаются до конкретных объектов и показывают полноту исходных сведений.
