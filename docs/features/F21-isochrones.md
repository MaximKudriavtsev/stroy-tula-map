# F21. Пешеходные изохроны 10–15 минут

**Цель:** MVP даёт честную оценку доступности; V2 закрывает требование настоящих пешеходных изохрон.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2 или обязательная функция по критериям
**Исполнитель:** GIS / интеграции

## Готовый промпт для агента

Ты реализуешь фичу F21 «Пешеходные изохроны 10–15 минут» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F03, F05; routing provider с pedestrian graph для настоящих изохрон.

**Условие интеграции:** Оценка радиусом допустима только как явно названный отдельный режим, не как выполненная изохрона.

**Потребляет:** Проверенная точка входа/anchor, pedestrian routing adapter, длительность, версия дорожных данных.

**Предоставляет:** Isochrone polygon с mode/method/provider/dataVersion/source/calculatedAt и отдельный APPROXIMATE_RADIUS mode.

## MVP — реализовать сейчас

1. Без routing доступа реализовать приближённую зону расстояния: выбранные 10/15 минут × явно заданная скорость 4 км/ч → приблизительно 667/1000 м. Подпись «Оценка по расстоянию, без учёта дорог и препятствий». Не называть этот круг пешеходной изохроной.
2. В mode=APPROXIMATE_RADIUS вычислять геодезический buffer, не градусный круг. Для неизвестной точки объекта расчёт недоступен.
3. Если есть валидные заранее рассчитанные пешеходные полигоны с источником, загрузить их как отдельный method=PRECOMPUTED_PEDESTRIAN и показать реальные metadata.
4. Слой не объявляет территорию официального обслуживания и не считает население внутри автоматически.
5. GET isochrones возвращает geometry, method, minutes и источник; ошибка провайдера не возвращает approximation под тем же method.
6. В карточке переключатель 10/15 минут, объяснение метода и скрытие слоя.

## Проверяемые сценарии MVP

1. Приближённый круг всегда помечен approximation; provider failure не маскируется.
2. Нет точки входа → понятная недоступность.
3. Размер буфера соответствует метрам, проверка на широте Тулы.
4. Два режима имеют разные cache keys и легенду.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.

## V2 — отдельное задание после приёмки MVP

Исполнять только если выбран режим V2. Вход — принятый MVP этой фичи; внешние зависимости перечислены в шагах.

1. Подключить согласованного routing provider, документированно поддерживающего пеший профиль. Проверить вход, барьеры/реки/переходы и доступные лицензии данных.
2. Кэшировать origin/profile/minutes/providerDataVersion; выполнять расчёт worker job и возвращать state QUEUED/READY/FAILED.
3. Проверить на контрольных маршрутах, что polygon следует дорожной сети и не обозначает пересечение непроходимого барьера как простой радиус.

Приёмка V2: все сценарии MVP проходят; для каждого нового поведения добавлена проверка успешного пути и указанного отказа.

## TARGET — отдельное задание после приёмки V2

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Развернуть собственный pedestrian graph и его обновление, если подтверждена такая эксплуатационная потребность.
2. Добавить доступность для маломобильных групп только при наличии необходимых атрибутов сети и проверенной методики.
3. Расчёт покрытия населения выполнять отдельной методикой с устранением двойного учёта пересекающихся зон.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F21
pnpm test:integration -- --feature=F21
pnpm test:e2e -- --feature=F21
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F21.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** MVP даёт честную оценку доступности; V2 закрывает требование настоящих пешеходных изохрон.
