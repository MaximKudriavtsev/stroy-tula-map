# F23. Камеры стройки и таймлапсы

**Цель:** Медиа отражают свой реальный источник и время; публичная камера доступна только при проверенном разрешённом потоке.
**Архитектура:** модуль существующего монорепозитория по contracts v1; разделённые production adapters и fixtures.
**Стек:** общий стек из 00-common.md; новые зависимости согласуются с интегратором.
**Приоритет:** P2 или обязательная функция по критериям
**Исполнитель:** Медиа / интеграции

## Готовый промпт для агента

Ты реализуешь фичу F23 «Камеры стройки и таймлапсы» портала строительства Тульской области.
Прочитай docs/agent-prompts/00-common.md, docs/agent-prompts/01-contracts.md и этот файл полностью. Если пакет приложен отдельно, используй эти документы из его корня. Не проси пользователя повторять сведения из них.
Режим по умолчанию — MVP. Выполни его до проверяемого результата. Если пользователь явно выбрал V2 или TARGET, сначала проверь принятую предыдущую реализацию и выполни только соответствующее приращение. Не переписывай готовый MVP.
Ты не один в репозитории: сохраняй чужие изменения, соблюдай границы файлов. Общие DTO, корневые конфиги и lockfile изменяет интегратор. Внешний доступ не подменяй фиктивным успешным ответом.

## Вход и зависимости

F00, F02, F03/F06; разрешённые камеры/потоки и права на публикацию.

**Условие интеграции:** Только явно одобренные публичные источники. RTSP URLs и credentials в браузер не выдавать.

**Потребляет:** Approved camera source, objectId, timestamps, privacy/publication policy.

**Предоставляет:** Список камер, состояние актуальности, снимки/видео с датой; optional streaming adapter.

## MVP — реализовать сейчас

1. Без камеры реализовать блок текущих фотоснимков через F02; подписать датой съёмки. Не показывать LIVE на загруженном файле.
2. При наличии разрешённого snapshot endpoint настроить server-side adapter с allowlist hosts, timeout/size limits и проверкой redirect. Не принимать произвольный URL для proxy.
3. Хранить latest valid frame и capturedAt; если источник не обновился, показывать «Последний снимок» и возраст, не «Онлайн».
4. Включить opt-in VIDEO MP4 в F02 и проверить контейнер/лимит. Предварительно подготовленный таймлапс загружать как публичный approved asset с периодом и источником. Не выдавать видеозапись за текущую камеру.
5. Публичный ответ не содержит исходные credentials. Ошибка камеры не ломает карточку и карту.

## Проверяемые сценарии MVP

1. Старый кадр имеет stale label, отсутствие источника — пустое состояние.
2. Запрос к неразрешённому/private network адресу заблокирован.
3. Credentials не присутствуют в public JSON, DOM и логах.
4. Ошибка камеры не влияет на загрузку object detail.

Для бизнес-логики сначала реализуй перечисленные сценарии как падающие тесты, проверь ожидаемую причину падения, затем добавь реализацию. Для UI проверь действия через браузер и сохрани доказательство поведения. Контракт API проверяется общими schemas.


## TARGET — отдельное задание после приёмки MVP

Исполнять только если выбран режим TARGET. Сначала сохранить совместимость и данные принятой предыдущей версии.

1. Подключить одобренный HLS/WebRTC поток; если источник RTSP, использовать выделенный media gateway с ограничением ресурсов.
2. Реализовать генерацию таймлапсов worker-ом, retention и пропуски кадров, соблюдая правила публикации.
3. Добавить health/latency monitoring, несколько камер объекта, автоматическое переключение на последний снимок с явной маркировкой.

Приёмка TARGET: перечисленные целевые поведения работают на согласованных данных и доступах, сценарии предыдущих версий проходят, миграции проверены на непустой БД. Если внешний источник недоступен, локальный adapter может быть готов, а внешняя приёмка остаётся открытой.

## Проверки и передача

Запусти после реализации соответствующие изменениям команды из 00-common.md:
```bash
pnpm typecheck
pnpm contracts:check
pnpm test:unit -- --feature=F23
pnpm test:integration -- --feature=F23
pnpm test:e2e -- --feature=F23
pnpm build
```
Не запускай неподходящую категорию как формальность: в handoff объясни, какие из unit/integration/e2e применимы этой фиче и какие реально выполнены. При применимом тестовом наборе ноль сценариев — ошибка проверки.
Подготовь docs/handoffs/F23.md по 02-handoff.md: изменённые файлы, exports, точное подключение, env, миграции, проверки, известные ограничения и интеграционный сценарий.
**Критерий завершения:** Медиа отражают свой реальный источник и время; публичная камера доступна только при проверенном разрешённом потоке.
