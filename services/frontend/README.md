# Карта строительства Тульской области

Каркас публичной карты. Базы данных пока нет: объекты берутся из локальной заглушки.

## Запуск

1. Скопируйте `.env.example` в `.env.local` и укажите ключ Яндекс Карт.
2. В кабинете API для ключа добавьте HTTP Referer: `http://localhost:3000/*`
3. Запустите проект:

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## Что уже есть

- Next.js (App Router) + TypeScript + Tailwind
- Полноэкранные Яндекс Карты (JS API v3), центр — Тульская область
- Строительные объекты из `src/data/objects.ts` / `places.csv`
- Режим **Доступность**: тепловая карта покрытия по POI OpenStreetMap (`src/data/osm-pois.json`)
- Режим **Обеспеченность**: та же карта, но с учётом плотности населения и нормативов

## Режим «Обеспеченность»

«Доступность» показывает абсолютную плотность объектов, поэтому чистое поле выходит
красным — объектов там нет, хотя обслуживать некого. «Обеспеченность» сравнивает число
объектов с нормативной потребностью местных жителей:

```
людей в радиусе обслуживания / норматив = объектов нужно
объектов фактически / объектов нужно    = обеспеченность
```

Обеспеченность 1,0 — норматив выполнен, она приходится на середину шкалы. Территории
без жителей закрашены серым, а там, где людей слишком мало и норматив объекта не
требует, — бежевым: это не дефицит. Фильтры «Все» и «Инфраструктура» в этом режиме
недоступны: сводный слой нечитаем, а инфраструктура слишком разнородна для одного
норматива.

### Нормативы

`src/data/provision-norms.ts`. Радиусы обслуживания — СП 42.13330.2016, таблица 5 и п. 10.5.

| Категория | Радиус | 1 объект на | Норматив |
| --- | --- | --- | --- |
| Образование | 750 м | 1 900 чел. | СП 42.13330.2016, прил. Д |
| Здравоохранение | 1000 м | 6 000 чел. | Приказ Минздрава России от 27.02.2016 № 132н |
| Спорт | 1500 м | 5 700 чел. | СП 42.13330.2016, прил. Д |
| Инфраструктура | 1000 м | 8 000 чел. | Распоряжение Минкультуры России от 02.08.2017 № Р-965 |
| ЖКХ и парки | 500 м | 1 000 чел. | СП 42.13330.2016, п. 9.8 и табл. 9.2 |

Два допущения, которые важно помнить при чтении карты:

- **Мощность объекта.** Нормативы заданы в местах и м², а у POI из OpenStreetMap мощности
  нет, поэтому «1 объект на N человек» получено через мощность типового объекта (школа
  около 500 мест, спортзал 400 м² и так далее). Это допущение, а не норматив; оно записано
  в поле `capacityAssumption`.
- **Сельская доступность.** СП допускает для села доступность 30 минут транспортом, а мы
  применяем единый городской радиус, то есть недооцениваем доступность на селе.

Норматив по образованию СП привязывает к демографической структуре, а не к общему числу
жителей: 100 и 180 мест на 1 тыс. чел. из приложения Д даны для новостроек при отсутствии
данных. Тульская область — одна из самых старых по среднему возрасту, поэтому взята
фактическая структура по данным Туластата.

## Обновление данных для теплокарт

```bash
npm run fetch:pois        # POI OpenStreetMap
npm run fetch:population  # сетка населения
```

`fetch:pois` запрашивает Overpass API по Тульской области и перезаписывает
`src/data/osm-pois.json` (ODbL / © OpenStreetMap contributors).

`fetch:population` скачивает Kontur Population (H3 res 8, ~400 м), обрезает его по контуру
области и пишет `src/data/population-grid.json` — 12 369 гексов и 1,42 млн человек, около
250 КБ. Лицензия ODbL; данные построены на GHSL, Microsoft/Facebook Buildings и OSM.
В конце скрипт печатает обеспеченность по области целиком, чтобы нормативы можно было
сверить с реальностью: сейчас все категории укладываются в диапазон 1,0-1,4.
